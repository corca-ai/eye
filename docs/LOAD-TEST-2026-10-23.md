# Cloudflare 실배포 부하테스트 — 2026-10-23

후속 코드 수정·독립 DO 프로브·재측정은 [DO 점검 기록](DO-REVIEW-2026-10-23.md)을 참고한다. 이 문서의 수치는 수정 전 측정으로 보존한다.

이번 실행은 정상 상태의 처리 용량을 확정하는 벤치마크가 아니다. 실제 계정의 Durable Object 저장소 타임아웃이 Eye 없는 기준선에도 발생했고, Queue 지표 API에서도 500 오류가 관찰됐다. 높은 부하로 진행하기 전에 이 조건을 분리해야 한다.

## 환경과 재현

- 원본: `5f71daf`에 아래 분석 HTTP 호출 수정과 `benchmarks/cf-load/` 하네스를 추가한 작업 트리.
- 관리·배포: `cf` 1.0.0-beta.20, Cloudflare Vite plugin 2.0.0-beta.v.4, Vite 8.0.3. 테스트 구성은 Wrangler를 실행하지 않는다.
- 부하 발생기: 로컬 macOS arm64, k6 2.3.0. 고정 도착률, iteration당 HTTP 요청 한 개, 요청 제한 10초.
- 보조 Eye Worker와 호스트 Worker를 Service Binding으로 연결. SQLite DO 5개 클래스와 호스트 세션 DO, Queue·DLQ, Stream·Pipeline, R2 Catalog의 분석 테이블 7개를 실제 생성했다.
- 기준선과 Eye 모드 모두 같은 호스트 세션 DO를 읽고 같은 크기(4,096바이트)의 JSON 응답을 만든다. Eye는 로컬 decide와 비동기 노출·로그·골 전달을 추가한다. 호스트 세션 원격 조회는 SDK의 로컬 결정 비용과 별도로 기록한다.
- 실험 3개 × arm 3개. 한 실험은 기본 7일 관측, 두 실험은 완료·재배정 검증용 2분 관측이다. 고정 사용자 풀 400명, 측정 요청의 5%는 신규 세션, 나머지는 재방문이다. 고정 사용자 풀의 절반은 uid를 공급한다.
- 분석·카탈로그·R2 임시 토큰은 3시간 만료이며 값은 저장소에 포함하지 않는다. `.state/`, 생성 빌드와 원시 결과는 gitignore한다.

재현 하네스는 소스 저장소의 `benchmarks/cf-load/README.md`를 따른다. 생성된 리소스·버전·계정 식별자는 로컬 `.state/`에 보관한다. 원시 k6 결과와 Queue JSONL은 `benchmarks/cf-load/results/`에 있다.

## 기능 확인에서 발견하고 수정한 오류

1. `BasinAnalytics`가 전역 fetch를 객체 멤버로 호출해 Workers에서 `Illegal invocation`이 발생했다. 실제 Worker에서 직접 호출은 성공하고 멤버 호출은 실패하는 것을 확인했다. 기본 fetch를 globalThis에 바인딩했다.
2. Workers는 `redirect: "error"`를 지원하지 않는다. 실제 Worker에서 해당 TypeError를 확인하고 `manual`로 변경했다. 3xx는 기존 HTTP 실패 처리로 넘겨 토큰을 다른 주소에 자동 전달하지 않는다.

두 조건을 재현하는 회귀 테스트를 추가했다. 수정 전 실패, 수정 후 성공을 확인했고 전체 테스트·타입·빌드·생성 문서 검사와 외부 소비자 패키지 검사가 통과했다. 수집·배정·로그인 인계·실제 분석 조회도 배포 환경에서 확인했다.

부하 종료 후 로그에서 `Future statistics snapshot` 거절도 확인했다. 내부 shard의 시각이 coordinator보다 앞설 수 있는데 같은 벽시계라고 가정한 검증이 통계를 거절했다. 내부 snapshot의 시각은 정수 timestamp로 검증하고, 정책 집계는 현재 시각과 보유 snapshot 시각의 최댓값에서 수행하도록 수정했다. 과거로 역감쇠해 가중치를 키우지 않으며 예약 만료는 실제 coordinator 시각을 유지한다. source가 앞선 두 shard 병합과 eviction 후 재조회를 회귀 테스트로 검증했다. 이 수정은 위 부하 숫자 수집 **이후** 적용됐으므로 해당 숫자는 수정 후 성능의 증거가 아니다. 외부 사건의 미래 시각 검증은 그대로다.

설치 과정에서는 `cf` 복합 플래그의 union 검증 때문에 Catalog sink 생성에 JSON body를 사용했다. Pipeline 바인딩의 `name` 필드에는 실제 Stream ID가 필요했다. 분석 자격 증명에는 Catalog·SQL 외에 R2 Storage 권한도 필요했다. 이들은 테스트 하네스의 provisioning에 반영했다.

## 서버 측 근거와 해석

여러 Subject DO에서 다음 오류와 객체 재시작이 기록됐다.

```text
Durable Object storage operation exceeded timeout which caused object to be reset.
```

문제가 발생한 실행의 CPU는 수 ms인 반면 wall time은 수십 초였다. GraphQL 지표에서도 호스트 Session 및 여러 Eye namespace의 `fatalInternalErrors`가 관찰됐고, 조회한 범위에서 CPU·메모리 한도 초과는 0이었다. 정상적인 CPU 포화가 원인이라는 근거는 없다. 플랫폼·배치 위치·저장소 경로를 추가로 조사해야 하며, 이 오류를 라이브러리의 처리 용량 한계나 Cloudflare 전체 장애로 단정하지 않는다.

`performance.now()`로 측정한 로컬 Eye 구간은 이 실행에서 모두 0ms였지만 Workers 타이머 해상도에 따른 결과다. CPU 비용이 없다는 뜻은 아니다. 외부 응답 시간, 호스트 세션 시간, Worker CPU, waitUntil을 포함하는 실행 wall time을 구별한다.

HTTP 응답이 타임아웃되어도 서버의 비동기 수집은 진행될 수 있으므로 성공 응답의 submitted 합계만으로 유실률을 계산하지 않는다. 수집 원본을 event ID로 대조하고 처리되지 않은 Queue·DO outbox까지 확인하기 전에는 정확한 유실률이나 중복률을 주장하지 않는다.

## Eye 본 측정의 참여와 처리 지연

Eye 본 측정에서 응답으로 확인한 결정은 8,979개이며 배정 6,398개, 미참여 2,581개(28.74%)였다. 신규 세션은 100% 미참여였고, 재방문 결정에서도 24.96%가 미참여였다. 미참여 사유는 cold 126, unprepared 1,643, invalid_state 812개였다. invalid_state에는 토큰 만료도 포함되므로 모두 위조나 구현 오류라는 뜻은 아니다. 성공한 재사용은 fresh 6,212개, stale 186개였다.

이는 신규 사용자 5%와 2분 관측 설정의 영향을 받으며, 사이트·캐시·세션 준비의 초반 구간도 포함한다. 준비 완료 사용자만의 정상 상태 미참여율을 측정한 값은 아니다. 그래도 이 연동 조건의 재방문 미참여율은 1% 목표를 충족하지 못했다. 빠른 HTTP 응답만으로 합격시키지 않는다.

응답으로 확인한 로컬 accepted 제출은 9,757건, 로컬 거절은 0건이다. 실제 전달 완료 건수와 다르다. Queue는 샘플 기준 최대 7,795건, 가장 오래된 메시지는 약 4분 26초였다. 부하 종료 약 54초 뒤 Queue가 0으로 관측됐고, 이후 5분 이상 확인한 샘플에서도 Queue·DLQ는 0이었다. 원시 events의 고유 record ID 수는 exposure 6,398 + goal 366 + track 2,993 = 9,757로 응답에서 확인한 제출 합계와 일치했다. 성공 응답별 전체 ID 집합을 부하 발생기에 저장하지 않았으므로 개별 ID 단위의 무유실 증명으로 확대하지 않는다. 지표 API의 일부 0값과 오류 샘플 사이에 큰 변동이 있어 이 값들을 정확한 동기 카운터로 취급하지 않는다.

## 실행 상태와 다음 단계

10 req/s의 기준선·Eye 모드 5분 측정을 완료했다. 기준선 저장소 오류, 높은 미참여율과 Queue 지연 때문에 100·200 req/s 및 15분 지속 측정은 실행하지 않았다. 먼저 저장소가 안정된 환경에서 기준선을 재확인하고, 호스트 세션 조회 비용과 SDK 결정 경로를 분리한다. 이후 요청 간 토큰 준비·갱신과 학습 소비 경로를 측정한 뒤 부하를 올린다.

기준선과 Eye 측정은 서로 다른 시각에 실행됐고 저장소 상태가 변했다. Eye의 p99가 기준선보다 낮다는 사실을 Eye가 지연을 개선했다는 증거로 해석하지 않는다. 이번 숫자를 정상 운영 비용이나 장기 MAB 학습 품질로 외삽하지 않는다.

최종 로컬 검증은 96개 테스트, 타입·빌드·생성 문서 검사와 하네스 타입 검사다. 배포된 테스트 리소스와 접근 secret은 로컬 상태에 보관하며, 임시 분석 토큰은 만료 후 갱신해야 한다. 커밋·푸시는 이번 실행에서 수행하지 않았다.
