# 신원·행동 존재·귀속 분모를 구간과 누적값으로 계산하기

[조회 구조](QUERY-STRUCTURE.md) · [검증 범위](IMPLEMENTATION.md) · [정책 시간 변화 검토](POLICY-TIME.md)

기준은 `020d2bd`다. 공개 분석 결과와 수집·학습·정책 수학을 유지하며 원본 SQL의 중간 조합을 줄인다. 정렬과 입력 읽기는 남고, 모든 쿼리가 O(1)이 되는 변경은 아니다.

## 신원 경계

노출과 identify/logout을 cid별 `(occurred_at, record_id)`로 합쳐 정렬한다. 같은 위치의 신원 사건을 먼저 둔다. 신원 사건에 1, 노출에 0을 부여해 누적하면 각 노출의 이전 신원 사건 번호 k를 얻는다. 이전 경계는 k, 다음 경계는 k+1로 동등 조인한다. 경계 전부와 노출을 시간 조건으로 연결해 순위를 매기지 않는다.

반복 로그인·계정 변경·로그아웃을 원본 순서대로 유지한다. 경계가 없으면 이전/다음 정보는 null이다. 원본의 중복 제거, 보존 하한과 수신 시각 상한도 동일하다. 시간순 정렬 후의 누적 처리와 번호 조인이 핵심이며 실제 물리 실행은 Basin 계획에 달려 있다.

## hasEvent

먼저 track 이름·속성 조건을 적용한다. 관측의 첫 노출로부터 다음 소유권 경로의 탐색 시작점을 만든다.

- 명시적 uid: 첫 노출 이후의 같은 uid 행동.
- 익명 cid: 첫 노출 이후·다음 신원 경계 이전의 익명 행동.
- 첫 로그인으로 연결될 익명 관측: 해당 로그인 이후의 uid 행동.

탐색 시작점은 관측 시작보다 앞설 수 없다. 각 경로에 시작점과 track을 합쳐 정렬하고 track 개수를 누적한다. 시작점의 누적 번호가 n이면 n+1번 track만 확인한다. 같은 위치에서는 시작점을 먼저 두어 시작 경계를 포함한다. 그 track이 관측 종료/신원 경계 밖이면 이후 track도 조건을 만족할 수 없다. 관측당 최대 두 소유권 탐색 결과만 중복 제거한다.

관측 관계를 DISTINCT로 먼저 확정한 뒤 소유권별로 나눈다. 로컬 SQLite에서 이 단계 없이 관계를 분기하자 projection/경계 조인이 재확장되어 후보 수 감소에도 느려졌다. EXPLAIN으로 반복 확장을 확인하고 관측 키를 먼저 확정한 뒤 재측정했다. SQL은 특정 엔진의 MATERIALIZED 확장에 의존하지 않는다.

## 특정 실험의 분모와 보상 분리

모든 노출에 원래 `(occurred_at, record_id)` 순서의 순위를 부여한다. 명시적 uid와 익명 cid는 노출 때, 로그인으로 연결된 익명 노출은 로그인 때 소유권 후보가 활성화된다. 후보의 활성화 시각과 원래 노출 순위를 구분한다.

소유자·실험별로 활성화 순서의 누적 최대 노출 순위를 구하고 실제 최대가 바뀐 지점만 남긴다. 늦은 로그인으로 오래된 노출이 연결되어도 더 새로운 노출을 덮어쓰지 않는다. 같은 로그인 위치에서 여러 노출이 활성화되면 가장 최신인 하나만 선택한다.

각 최신 선택의 구간 종료는 다음 선택, 익명 cid의 다음 신원 경계, 귀속 만료 중 가장 빠른 위치다. 최신 선택을 먼저 정한 뒤 귀속 만료를 적용한다. 이미 만료된 새 선택도 이전 선택을 종료하므로 과거의 긴 귀속 기간으로 되돌아가지 않는다. 관측 마감은 귀속 구간을 자르지 않는다. 마감된 다른 실험도 귀속 유효 기간이면 분모에 남는다.

귀속 만료는 `gap <= horizon`이므로 만료 밀리초의 모든 event ID를 포함해야 한다. 시간·위상·ID 순서를 사용해 실제 사건은 위상 1, 귀속 만료는 위상 2에 둔다. 다음 노출/로그인 경계는 위상 1에서 배타적으로 종료한다. 같은 경계의 시작·종료 변화는 골을 읽기 전에 적용한다.

유효 구간 시작에 +1, 종료에 -1을 기록해 소유자별 누적하면 골의 경쟁 실험 수 K를 얻는다. 실험과 구간 키를 유지한 채 끝점을 합쳐 같은 시각의 서로 다른 실험을 중복 제거하지 않는다. 전체 실험은 끝점으로 분모에 참여하고, 요청 실험의 골-노출 매칭과 보상만 생성한다. arm·generation·goal·속성 필터는 기존 위치에서 적용하며 분모를 바꾸지 않는다. 전체 credit 행을 반환하는 타임라인은 기존 귀속 경로를 유지한다.

## 검증과 로컬 측정

변경 전 쿼리 두 파일 `reference-sweep-attribution.ts`, `reference-sweep-sql.ts`는 검증/측정 전용이며 제품 패키지와 런타임에서 사용하지 않는다. 회귀 검사는 반복 신원 경계, 같은 시각 ID, 재전송, 다른 기기, 늦은 익명 연결, 만료 시각 포함, 만료된 최신 선택, 동시 다중 실험 시작, 소유자별 모든 골의 K, 전체 대상 credit 열, hasEvent 이름·속성 필터, arm/시계열 집계를 비교한다. 혼합 스트림은 고정 시드 8개와 실제 증분 엔진이 마감한 관측을 사용한다. 집계 합산 순서의 부동소수점 차이는 작은 허용 오차로 비교하고 개별 credit 행과 분모는 정확히 비교한다.

[원시 결과](measurements/query-sweeps-results.json)는 동일 입력, 한 번 예열과 세 번 실행의 중앙값이다. Node.js 메모리 SQLite에서 실행했으며 시간은 ms다.

| 검사 | 입력 | 중간 작업의 변화 | 이전 ms | 현재 ms |
| --- | --- | --- | ---: | ---: |
| 신원 경계 | 노출 320 + 신원 320 | 잠재 노출×신원 조합 102,400 → 병합 스트림 640행 | 93.22 | 3.50 |
| hasEvent 포함 arm 조회 | 관측 320 + track 320 | 일치 조합 102,400 → 탐색 시작점 320개 | 508.32 | 41.11 |
| 특정 실험 보상 | 동시 실험 128, 골 200 | 전체 적격 행 25,600 → 끝점 512 + 대상 매칭 200행 | 293.91 | 19.88 |

같은 골 200개에서 동시 실험이 1개이면 분모 경로는 7.64→9.98ms, 2개이면 9.15→10.04ms로 고정 비용이 늘었다. 4개에서는 12.05→10.70ms였다. 이 변경은 모든 크기에서 지연을 줄인다는 보장이 아니라 실험 수와 골 수의 곱으로 생기는 중간 결과를 줄이는 선택이다.

서로 다른 종류의 중간 작업을 비교한 계수이며 SQL 명령 수·물리 읽기 수·Cloudflare 과금 단위가 아니다. 원본 읽기와 정렬은 계속 필요하다. 각 측정은 전체 관련 쿼리의 결과 일치를 먼저 확인한다. 작은 입력의 고정 비용과 실제 Basin의 실행 계획·window 예산·스캔 바이트·분산 조인 성능은 별도로 확인해야 한다.

```sh
npm run build
node_modules/.bin/esbuild benchmarks/analytics/query-sweeps.ts --bundle --platform=node --format=esm --outfile=/tmp/eye-query-sweeps.mjs
node /tmp/eye-query-sweeps.mjs
npx vitest run --project core test/core/query-sweeps.test.ts
npm run check
npm run check:package
```

지원 연산은 [Basin SQL](https://developers.cloudflare.com/basin-sql/sql-reference/#window-functions)의 누적 SUM/MAX, LAG/LEAD, 동등·구간 조건 조인이다. 실제 적용 환경에서 [EXPLAIN과 predicate pushdown](https://developers.cloudflare.com/basin-sql/reference/limitations-best-practices/)을 확인한다. 이 변경은 원격 배포를 수행하지 않는다.
