# 구현 재점검 — 2026-10-23

설계와 코드, 로컬 workerd/SQLite 실행, 배포 tarball을 대조했다. 아래 결함은 수정 전 실패를 재현한 뒤 수정했다. 이 결과는 모든 버그의 부재나 실제 Cloudflare 운영 검증을 뜻하지 않는다.

## 수정한 결함

학습 만료 처리는 무손실 복구를 뜻하지 않는다. 60일을 넘긴 장애로 학습 반영을 놓친 경우를 경고로 드러내고, 이후 항목 처리를 계속한다. 정상 보관 범위의 실패를 무시하거나 누락 보상을 0으로 대체하지 않는다.

가입 보상 회귀 검사도 수정했다. 관측창이 100ms인데 goal 시각을 여러 RPC 이후의 실제 시계로 만들면, 느린 테스트 실행에서 정상적으로 창 밖에 놓였다. goal의 사건 시각을 익명 배정 시각으로 고정하고 수신 시각과 분리했다. 제품의 관측창 의미나 오류 처리를 완화하지 않았다.

## 계획과의 대조

uid 우선, 신규 uid의 익명 상태 인계, 공통 goal의 균등 귀속과 시간 감쇠, 완료된 0 보상, signed 보상, 망각과 탐색을 포함하는 장기 선택 정책, 최소 arm 유지, 비동기 수집, 분석 API는 로컬 구현·검사 대상에 포함되어 있다. 개별 검증 범위는 [구현 상태](IMPLEMENTATION.md), 분석 의미와 한계는 [분석 계약](ANALYTICS.md)을 따른다.

**아직 계획과 완전히 일치하지 않는 경계가 있다.** 기존 uid가 일부 실험 상태를 이미 가진 경우, 새 cid에만 있는 다른 실험의 상태를 개별적으로 인계하는 경로는 미완료다. 현재 상태 위치가 uid 단위로 고정되어 있기 때문이다. 배정만 복사하면 진행 중 관측과 보상 귀속을 잃을 수 있으므로, 상태 이전·지연 이벤트 라우팅·재시도까지 함께 해결해야 한다. 이번 수정으로 이 항목이 해결되었다고 간주하지 않는다.

Identity Registry의 장기 메타데이터 정리와 다중 기기·계정 전환 중 RPC 실패 검증도 남아 있다. 실제 Basin SQL 엔진의 JSON·타입 반환, Stream에서 Catalog까지의 전달, 실계정 설치, 수천만 행 조회 성능과 비용은 로컬 검사로 증명하지 않았다. 60일 이전 데이터의 보관 정책은 합의대로 후속 범위다.

## 검증

- `npm run check`: 엄격한 TypeScript 검사, 61개 검사 통과, JS·타입 선언 빌드 성공.
- `npm run check:package`: 별도 임시 디렉터리에 tarball을 풀고 공개 API·배포 예제 타입 검사, 문서 상대 링크 확인, 생성 Worker의 Wrangler dry-run 수행.
- 실제 Cloudflare 리소스 생성이나 배포는 수행하지 않았다.

수정한 런타임 경로는 `src/core/attribution.ts`, `src/core/events.ts`, `src/core/validation.ts`, `src/runtime/subject.ts`다. 회귀 검사는 `test/core`와 `test/runtime`에, 패키지 검사는 `scripts/check-package.mjs`에 있다.
