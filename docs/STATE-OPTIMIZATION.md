# 증분 상태 최적화 검증

2026-10-25. 비교 기준은 `5eeb1fd31de912b7e6f473c25aa10334e30668aa`의 증분 엔진이다. 원본 반복 조회 제거 이전과의 비교가 아니다.

## 변경

- goal만 event ID별 최초 accepted/rejected 판정을 유지한다. 신원은 순서 키의 엄격한 증가, 노출은 최근 참조/최초 메타데이터의 최대·최소 갱신으로 재시도를 처리한다. 이전 혼합 중복 기록은 정상 만료까지 둔다.
- 마지막 노출 전체 JSON 대신 순서 키·표본 ID·귀속 기간만 저장한다. 기존 행을 읽고 다음 실제 갱신에서 압축하므로 전체 이관을 수행하지 않는다.
- 한 배치의 상태 변경을 키별로 모아 저장한다. 사건 정렬·보상 합산 순서와 중간 신원 전이는 유지한다. 배치 밖으로 변경을 보류하지 않는다.
- 성공한 Stream chunk의 일별 사전 키만 isolate 내 최대 10,000개 기억한다. 실패와 동시 miss는 중복을 허용한다. 원본 사건/속성은 생략하지 않는다.
- 명시적으로 선택한 기본 요약만 시간별 건수·스케일 보정 합을 저장한다. 원본 조회 API의 시간·가시성 계약을 대체하지 않는다. 설정·coverage·한도·사용법은 [분석 가이드](ANALYTICS.md#원본-조회-없이-읽는-선택적-요약)를 따른다.

## 재현

```sh
npm run build
node benchmarks/compact-state/run.mjs --events=10000 --repeats=7 --output=/tmp/eye-state-after.json
```

이전 엔진을 별도 디렉터리에서 빌드한 다음 같은 현재 benchmark에 `--module=/absolute/path/to/previous/dist/runtime/incremental.js --output=/tmp/eye-state-before.json`을 전달한다. module 옵션은 이전 엔진 비교용이며 선택적 요약 실행을 생략한다. 사전 비교는 두 실행 모두 현재 export 코드에서 캐시 유무를 바꿔 비교한다. 실행 당시 원시 반복 측정·해시는 `benchmarks/compact-state/results.json`에 보관한다.

입력 10,000개는 사용자 500명 × (로그인 1 + 노출 8 + goal 2 + track 9)다. 두 실험, 사용자당 표본 두 개이며 수신 중복도 추가한다. 입력을 미리 생성·정렬하고 학습 accept와 모든 close를 측정한다. 미완료 표본·goal 중복 기록·관측 outbox SQL을 포함하고 전송·outbox ACK는 시간/쓰기 측정에서 제외한다. 예열 한 번 후 7회 실행한다. 메모리 SQLite·Node 환경이며 네트워크, 디스크 fsync, SQL 인덱스 쓰기 과금, Cloudflare 운영 처리량·비용을 측정하지 않는다.

## 결과 해석

동일한 1,000개 표본의 보상 digest가 전후 및 요약 활성화에서 일치했다. 기본 경로의 SQLite 행 변경은 **14,003 → 9,503**, goal 중복 기록은 **5,500 → 1,000**, 마지막 노출 JSON 합계는 **565,900 → 83,560바이트**다. JSON은 payload 크기이며 전체 SQLite 파일·색인·실제 디스크 절감량이 아니다.

로컬 처리 시간 중앙값은 기본 경로 137.8 → 110.3ms였다. 단일 장비의 고정 순서 실행이며 운영 지연·처리량 보장이 아니다. 요약 활성화의 109.9ms와 기본 경로의 근소한 차이는 개선으로 해석하지 않는다. 사전 캐시는 100건 배치에서 약간의 CPU 부담도 관측됐으므로 전송량 절감과 CPU 절감을 동일시하지 않는다.

이 입력은 같은 사용자에 대한 goal들이 여러 배치로 나뉘므로 표본 쓰기 결합의 최대 이득을 나타내지 않는다. 별도 회귀 테스트에서는 같은 표본에 기여하는 100개 goal을 순서대로 계산하고 표본 쓰기를 한 번만 수행하면서 보정 합의 잔여값을 보존했다.

선택적 요약을 두 실험·한 goal에 활성화하면 총 변경은 **9,525건**으로 기본 경로보다 22건 많다. 5개 버킷 행을 보관하며 한 실험의 500개 완료 관측에 대한 조회는 2개 버킷을 읽는다. 여러 시간·세대·arm으로 분산되면 버킷 수도 늘어난다. 반복 조회가 드물면 이 추가 쓰기가 원본 조회 캐시보다 유리하지 않을 수 있다.

사전은 같은 UTC 날짜에 변하지 않는 20개 키의 track 10,000건으로 비교했다. 100개씩 전송할 때 사전 행 **2,000 → 20**, 전송 레코드 JSON 합계 **12,630,210 → 11,763,150바이트**다. 원본 10,000건은 모두 유지했다. 1건씩 전송하면 사전 행 200,000 → 20으로 이득이 커진다. 키·사이트·날짜가 자주 바뀌거나 isolate가 분산·재시작되면 효과가 줄고 캐시 조회 CPU도 발생한다. 이 고정 키 실험의 절감률을 일반 트래픽에 적용하지 않는다.

기존 `benchmarks/local-learning/run.mjs --sizes=10000 --repeats=3`의 ordered 및 배치 정렬 지연 입력도 기준 보상과 일치했다. 실제 지연 최초 도착을 전역 복구하지 않는 기존 근사 정책은 유지한다. 로그아웃 이전 익명 노출의 뒤늦은 최초 도착은 현재 귀속 참조를 복원하지 않도록 바꿨으며, 해당 무보상 표본은 남긴다.

## 회귀 검증 범위

로그인·로그아웃 중복, 로그아웃 이전 노출 재전송·늦은 최초 도착, 배치 안의 참조 이동·삭제, 롤백 뒤 같은 엔진 재사용, 기존 전체 JSON 참조와 rejected goal 호환, 마감된 참조의 분모 참여를 확인한다. 사전은 성공 전송만 캐시, 실패 재시도, 동시 miss, 용량 축출과 사이트·날짜·출처·타입 분리를 확인한다.

요약은 0 보상·음수·중복/거절 goal, 마감·outbox 재시도, 올바른 coverage 축, 전체 시간 경계, 재시작·롤백, 설정 초기화·용량 한도·만료, arm·세대·관측 기간 분리를 확인한다. 합계가 넘치는 버킷을 먼저 숫자 하나로 변환하지 않으며 `[1e308,1e308] + [-1e308]`과 `[1e16,1] + [-1e16]`의 유한한 최종 결과를 확인한다. 일반적인 임의 정밀도나 모든 부동소수점 입력에 대한 수학적 오차 보장은 아니다.
