# 문서·구현 대조 — 2026-10-23

**이 문서는 구현 전 대조와 후속 결정의 이력이다.** 네 합의의 후속 구현 상태는 [구현 상태](IMPLEMENTATION.md), 빠른 경로 계약은 [빠른 배정](FAST-DECISIONS.md)을 따른다. 아래 미구현 표현과 84개 테스트 수는 당시 상태를 기록한 것이다.

당시 작업 트리의 공개 클라이언트, Service Binding, 설정 검증, Experiment/Subject 상태 처리, 정책 계산, 분석 SQL·반환 타입과 주요 설계·사용 문서를 대조했다. 기존 미커밋 최적화도 포함한다. 실제 Cloudflare 배포 동작이나 비용을 새로 측정한 검토는 아니다.

## 수정한 코드 문제

공개 `experiments.create()`가 생략된 `correctionWindowMs`를 신규 기본값 7일로 채운 뒤 RPC를 호출했다. 따라서 필드가 없는 기존 실험을 원래 입력으로 다시 등록하면 DO의 이전 설정 보존 분기를 타지 못하고 다른 정의라는 오류가 발생했다. 이전 설정의 allowed lateness가 7일을 넘는 경우에는 클라이언트 검증부터 실패했다.

클라이언트에서 생략 여부를 보존하고, 저장된 실험을 아는 DO에서 신규 기본값·이전 정의의 호환성을 결정하도록 수정했다. 공개 클라이언트→Service Binding→실제 로컬 DO 경로의 회귀 테스트는 수정 전 충돌 오류로 실패했고, 수정 후 lateness 0일·8일의 기존 실험과 신규 실험의 7일 기본값을 확인한다. 명시한 정정 기한의 검증은 유지한다.

## 수정한 문서 문제

- 수집 검증 실패는 throw가 아니라 `{ accepted: false, error }` 반환이다.
- 분석 테이블의 공통 평면 열과 JSON payload를 구분하고 `processing_status` 대신 실제 `status` 열을 명시했다.
- `arms()`와 현재 `policy()`의 결과를 구분했다. score는 공통 scale로 나눈 값이며 평균은 원래 가치 단위다.
- `series()`는 사이트 goal 시계열이다. 속성 값 목록은 제공하지만 키·타입 사전이나 arm별 배분 시계열 API는 없다.
- 관측 설정은 배정 생성 당시 값이다. Subject alarm에는 보관 정리도 포함된다. 분석 응답은 실제 반영 완료 watermark를 제공하지 않는다.
- 안정적 모멘트와 로컬 통합 검사를 미구현으로 적은 오래된 상태 설명을 수정했다. 조회 캐시를 이미 적용했다는 표현도 제거했다.
- 현재 중앙 DO 배정 경로와 후속 SWR 계획을 구분했다. 지연 반영 허용이라는 후속 합의를 기존 즉시 중지 설명보다 우선하는 목표 계약으로 연결했다.

## 후속 결정과 남은 범위

1. **기존 uid의 실험별 인계:** uid에 다른 실험의 상태가 이미 있고 cid에만 이번 실험이 있으면 개별 인계가 연결되지 않는다. 후속 답변에서 **A: cid의 배정과 진행 중 관측·누적 보상을 uid로 인계**하기로 확정했다. 관측 시작 시각과 기존 배정 설정을 유지하며, 로그인 때문에 새 관측을 시작하지 않는다. uid에 이미 해당 실험의 배정이 있으면 기존 uid 우선 규칙을 적용한다. 동작은 확정되었고 상태 이전·지연 이벤트·실패 복구의 구현은 남아 있다.
2. **분석 API의 추가 범위:** 설계에는 배정·노출 횟수, arm별 시계열·실제 배분 비율·정책 변경 이력, 속성 키·타입 사전이 포함된다. 현재 전용 API는 없다. 원시 자료 보존과 전용 집계 제공은 다르므로 구현 완료로 표시하지 않았다. 후속 답변 **A**로 시간별 arm 성과·실제 배분 비율, arm별 배정·노출 횟수, 정책 선택 확률 변경 이력, 수집 속성 키·타입 목록을 모두 구현 범위에 포함하기로 확정했다. 상세 API 계약과 구현은 후속 작업이다.
3. **SWR의 허용 범위:** SWR·로컬 재사용은 명시된 미구현 계획이다. 후속 답변으로 fresh 60초·발행 후 최대 나이 5분과 실험별 참여 대상 요청의 미참여율 목표 1% 이하를 초기 기준으로 확정했다. 정책·안전한 배정이 준비되지 않으면 기다리지 않고 해당 요청의 실험을 건너뛴다. 지역·로그인 여부·신규 사용자별 편중도 확인하며 목표 초과 시 자동으로 요청 대기를 늘리지 않는다. 중지 반영도 최대 5분가량 지연될 수 있음을 허용한다. 실측 보장은 아니며 조정 가능한 값이다. 현재 `decide`는 RPC를 기다린다. 이번 대조를 이유로 기존 API를 갑자기 무대기·미참여로 바꾸지 않았다.
4. **실험·arm 삭제:** 후속 답변으로 일시중지는 재개 가능, 삭제는 재개 불가능한 영구 비활성화로 확정했다. 삭제 후에도 과거 기록·보상을 보존하고 삭제 전 노출의 지연 보상에는 기존 귀속·정정 규칙을 적용한다. 삭제한 실험 ID는 같은 사이트에서, 삭제한 arm ID는 같은 실험에서 재사용하지 않는다. 실험 전체 중지·삭제 시 모든 arm을 배정 대상에서 제외하며 정책 갱신 지연을 허용한다. 현재 API에는 실험 전체 중지·재개·삭제와 arm 영구 삭제가 없으므로 구현은 후속 작업이다.

## 검증

`npm run check` 통과: 10개 파일의 84개 테스트, 엄격한 타입 검사와 빌드 성공. `npm run check:package` 통과: 외부 소비자 타입 검사와 생성 Worker dry-run 성공(114.93 KiB / gzip 27.01 KiB). 패키지에 포함되지 않는 소스 파일로 연결한 문서 링크도 이 검사에서 발견해 경로 표기로 수정했다. 기존 workerd RPC disposal 경고와 의도된 중복 ID 거부 로그는 남아 있으나 테스트 실패는 없다. `git diff --check` 통과. 원격 배포·운영 부하 검증은 포함하지 않는다.
