# 정책 점수의 시간 변화: 4번 후보 검토

[현재 정책 구현](https://github.com/corca-ai/eye/blob/main/src/core/policy.ts) · [구현한 조회 개선](QUERY-SWEEPS.md)

이 문서는 검토 결과이며 정책 실행 코드는 변경하지 않는다.

## 성립하는 수학

새 학습·활성 arm·설정 변경이 없고 동일 generation의 학습 반감기를 h라 하면, 기준 시각 이후 모든 arm의 가중치는 공통 인자 c=2^(-Δt/h)로 감소한다. 같은 인자를 전체 가중치에 곱해도 각 arm과 전체의 가중 평균·분산은 변하지 않는다. 현재 계산은 arm별 감쇠와 전체 모멘트 병합을 매 정책 평가에서 다시 수행한다.

학습 가중치 w_i가 초기 탐색 기준 B 이상인 arm은 B>=1이므로 max(c*w_i,1)=c*w_i다. 이 arm들의 점수 순위는 공통 정규화 배율을 제외하면 다음 직선들의 순위와 같다.

U_i(t) = μ_i + b_i * X(t)

X(t) = sqrt(log(2+c*W)/c)

b_i = bonusMultiplier * max(σ_i, 0.25*S) / sqrt(w_i)

W는 기준 시각의 전체 가중치, S=max(rewardScale, 전체 표준편차)다. X는 c가 감소할수록 증가한다. 따라서 다음 직선 교점과 다음 warm→cold 전환 중 먼저 도달하는 시점까지 선택 확률을 유지할 수 있다. warm→cold 경계는 Δt=h*log2(w_i/B)다. 모든 arm이 cold라면 새 학습 없이 감쇠만으로 warm으로 돌아가지 않으며 균등 배정은 유지된다.

이론적으로는 점수선의 상한 포락선을 구해 우세 arm 변경 후보만 따라갈 수 있다. 모든 arm 쌍의 교점을 매번 비교하는 방식은 필요하지 않다. 다만 cold 전환으로 후보 집합이 바뀌면 포락선도 갱신해야 한다.

작은 로컬 대조에서는 모든 arm이 warm인 보통 크기의 유한 보상에서 현재 정책 함수와 위 직선식의 점수 4,800개를 비교했고 최대 절대 차이는 약 1.42e-14였다. 극단값·cold 전환·교점 경계의 전체 검증이나 성능 측정은 아니다.

## 보존해야 할 계약과 수치 한계

- 선택 확률이 같아도 weight·score·asOf는 시간에 따라 바뀐다. 통계 응답을 그대로 재사용하거나 발행 시각을 임의로 늘리면 안 된다.
- 현재 서버는 최대 한 시간/짧은 반감기의 1/8/호출자의 maxAge 중 가장 짧은 조건으로 재평가한다. 호스트는 기본 15분 재확인·발행 후 최대 6시간 재사용 계약을 갖는다. 이를 바꾸는 것은 별도 제품 결정이다.
- statsAsOf만 캐시 키로 쓰면 같은 시각에 추가된 학습을 놓친다. 기존 dirty 무효화와 설정 revision, arm 상태를 보존해야 한다.
- 수식은 실수 연산에서의 등가성이다. 현재 구현의 스케일 보정, 가중치 underflow, 작은 질량의 평균 대체, 정확한 점수 동률과 경계 반올림을 검증해야 한다. 교점 부근은 보수적으로 재계산하는 방법이 필요하다.

## 도입 판단

기본 정책 캐시가 이미 있고 통상 arm 수가 적다. 학습이 계속 들어오면 공통 감쇠만 있는 구간도 짧다. 따라서 조회의 대규모 조합을 줄이는 1–3번보다 실익이 작을 가능성이 높다.

첫 후보는 기존 재평가 주기를 유지하면서 변경 없는 통계의 공통 감쇠와 pooled 통계를 재사용하는 것이다. 이후 실제 프로파일에서 정책 계산이 병목일 때만 교점 기반 재평가를 검토한다. 정책 표본 가중치·탐색 의미·수신 유예를 바꿀 필요는 없다. 현재 단계에서는 도입을 보류하며 원격 성능이나 비용 절감률을 주장하지 않는다.
