# 지속형 MAB 설계 시뮬레이션

현재 로컬 배정·증분 학습 엔진의 A/A·A/B 및 로그 스트림 검증은 [현재 엔진 검증](ENGINE-VALIDATION.md)을 따른다.

2026년 10월 22일 실행한 설계 실험이다. [계산식](../TECHNICAL_DESIGN.md)과 [실행 코드](../scripts/simulate_bandit.py)를 함께 보관한다. 실제 SDK나 Cloudflare 처리 성능을 측정한 결과는 아니다.

## 재현

```sh
python3 scripts/simulate_bandit.py
python3 scripts/simulate_bandit.py --seeds 4 --half-life 7 --output docs/simulation-half-life-7.json
python3 scripts/simulate_bandit.py --seeds 4 --half-life 28 --output docs/simulation-half-life-28.json
```

Python 3.13.7의 표준 라이브러리만 사용했다. 기본 실행은 540일, 시드 0–7, 하루 100개 신규 관측, 관측 지연 7일, 학습 반감기 14일이다. 저트래픽과 장기 지연 시나리오만 해당 값을 변경한다. 비교 정책에는 같은 시드의 잠재 보상을 사용하고, 정책 선택 난수는 별도 생성한다.

비교 대상은 망각을 적용한 낙관적 점수, 같은 점수에서 망각만 끈 정책, 균등 무작위 배정이다. 앞의 두 정책은 동일한 pending 처리·초기 탐색·총 2% 균등 탐색을 사용한다. 망각을 끈 정책은 원 논문의 UCB1 구현이 아니다.

## 추세 변화 뒤의 선택

다음 수치는 새 최적 arm 선택률이다. 변경 시각에 관측 지연 W를 더한 뒤 30일 동안의 비율을 8개 시드에서 평균했다. 정상 환경은 초기 관측 지연 이후 30일, arm 추가 시나리오는 신규 arm 추가 이후 같은 방식으로 측정했다. 이는 실제 사용자의 가치 증가율이 아니다.

| 상황 | 망각 적용 | 망각 없음 | 균등 배정 |
| --- | ---: | ---: | ---: |
| 정상 환경 | 98.8% | 99.0% | 50.4% |
| 270일째 우수 arm 변경 | 83.3% | 1.0% | 49.8% |
| 240일 신규 arm 추가, 390일 중지 | 98.6% | 98.7% | 33.2% |
| 희소 구매와 음수 손실 | 82.7% | 33.8% | 50.2% |
| 큰 보상이 드문 분포 | 67.4% | 8.6% | 50.2% |
| 하루 8개 신규 관측 | 90.0% | 37.2% | 50.6% |
| 28일 관측 지연 | 82.7% | 1.0% | 50.2% |

큰 보상이 드문 시나리오에서 망각 적용 정책의 선택률은 시드별 40.6%–88.0%로 차이가 컸다. 평균만으로 안정적인 성공을 주장할 수 없다. 신규 arm은 탐색되었고, 중지 이후 새 배정은 모든 정책·시드에서 0건이었다.

## 전체 기간의 탐색 비용

아래는 배정마다 당시 최적 arm의 기대 보상과 선택한 arm의 기대 보상 사이 차이를 540일 전체에서 평균한 값이다. 낮을수록 좋다. 시뮬레이션에서 참 기대값을 알기 때문에 계산할 수 있으며, 서비스에서 그대로 관측할 수 있는 지표는 아니다.

| 상황 | 망각 적용 | 망각 없음 | 균등 배정 |
| --- | ---: | ---: | ---: |
| 정상 환경 | 0.0210 | 0.0066 | 0.2001 |
| 270일째 우수 arm 변경 | 0.0374 | 0.2246 | 0.3744 |
| 240일 신규 arm 추가, 390일 중지 | 0.0209 | 0.0085 | 0.2930 |
| 희소 구매와 음수 손실 | 0.2245 | 0.1626 | 0.7511 |
| 큰 보상이 드문 분포 | 0.1746 | 0.3593 | 0.7511 |
| 하루 8개 신규 관측 | 0.0866 | 0.0641 | 0.3764 |
| 28일 관측 지연 | 0.0829 | 0.4387 | 0.3744 |

정상 환경, 신규 arm 추가, 희소 구매, 저트래픽 시나리오의 전체 기간 지표에서는 망각 없는 정책이 더 좋았다. 망각은 적응성을 얻는 대가로 기존 관측을 덜 신뢰하고 탐색 비용을 지불한다. 이 결과는 모든 환경에서 망각 적용 정책이 우월하다는 근거가 아니다.

## 학습 반감기 민감도

공정하게 시드 0–3만 비교했다. 아래는 동일한 변경 후 30일 지표다. 7일·28일 실험을 기본 8시드 결과와 그대로 비교하지 않았다.

| 상황 | H 7일 | H 14일 | H 28일 |
| --- | ---: | ---: | ---: |
| 270일째 우수 arm 변경 | 92.2% | 81.6% | 80.3% |
| 희소 구매와 음수 손실 | 88.0% | 80.1% | 80.2% |
| 큰 보상이 드문 분포 | 84.5% | 64.4% | 50.1% |
| 28일 관측 지연 | 88.2% | 82.9% | 61.0% |

14일은 이 실험에서 찾은 최적값이 아니라 조절 가능한 시작값이다. 실제 관측 지연, 사용자 수, 가치 분포, 추세 변화 속도에 따라 달라진다.

## 검산한 규칙

- 양수·음수 보상의 모멘트와 감쇠, 표본 수를 늘리지 않는 지연 정정.
- 오래된 관측을 잊을 때 탐색 보너스 증가, 진행 중 관측을 0 보상으로 세지 않기.
- 균등 분배 후 부호를 유지한 시간 감쇠, 줄어든 몫을 재분배하지 않기.
- goal 이전의 마지막 노출 선택, 관측 종료 시각을 제외하는 구간 경계.
- 보상과 초기 척도를 1,000배 바꿔도 모든 시드에서 전체 선택 순서 일치.
- 중지된 arm에 신규 배정하지 않기.

단위 배율 검산은 보상과 초기 rewardScale을 함께 1,000배 바꾼 경우의 선택 일치다. 초기 척도를 고정해도 임의의 단위 변경에 자동 불변이라는 뜻은 아니다.

## 포함하지 않은 검증

- 실제 사용자 재방문, 기기 간 uid 통합, 진행 중 arm 강제 전환에 따른 표본 선택 편향.
- 여러 실험의 동시 상호작용과 사용자별 마지막 노출 원장을 통한 전체 귀속 처리.
- 각 관측 기간 안에서 분포가 계속 변하는 이벤트 스트림. 이 실험은 구간 시작 시각의 분포에서 합산 보상을 뽑고 W일 뒤 공개한다.
- Queue 역순·중복 전달, outbox, Basin 반영 지연. 일부 규칙의 산술 검산은 전체 전달 경로 통합 검사와 다르다.
- 평균·분산이 존재하지 않는 분포나 모든 형태의 무제한 보상에 대한 성능 보장.
- Cloudflare 리소스의 부하·비용·배정 지연 및 실제 6천만 행 SQL 조회.
