# 요청 경로 지연·비용 개선 계획 — 독립 리뷰 반영

이 문서는 설계 제안과 리뷰 이력을 보존한 문서다. 후속 구현은 [빠른 배정](FAST-DECISIONS.md)과 [구현 상태](IMPLEMENTATION.md)를 따른다. 로컬 재사용·SWR·서명 세션·중앙 준비와 lease 보호를 구현했으며, KV 발행·완전 로컬 신규 선택은 아직 후속 단계다. 아래 제안 전체가 구현되었다는 뜻은 아니다. 구현·배포된 동작이나 측정 결과가 아니다. 두 명의 독립 리뷰를 반영했다. 이후 사용자가 SWR 활용과 드문 콜드 요청 미참여를 허용하여 요청 경로의 기본값을 추가 수정했다. 이 추가 수정은 앞선 독립 리뷰 이후의 변경이다. 기존 DESIGN.md의 요구사항을 변경하는 구현 명세로 바로 사용하지 않는다. 아래 검증 관문을 통과한 범위부터 구현 명세에 반영한다.

## 목표와 허용하는 절충

고객의 Cloudflare Workers 인프라에서 동작하는 서버 API 라이브러리다. 요청 지연을 최소화하고, 사이트 공통 signed goal value를 장기간 비정상 환경에서 최적화한다. uid 우선, 실험별 최소 유지 기간, 실제 노출에서 시작하는 고정 관측창, 완료 0 보상, 지연 정정, 시간 감쇠를 유지한다. 최근 60일 분석을 지원한다. 하루 100만 이벤트는 배정 조회 수나 활성 실험 수의 상한이 아니다.

점수·선택 확률·실험과 arm의 운영 변경은 지연 반영할 수 있다. 이를 **배포된 정책으로 판단하고 비동기로 학습한다**는 원칙으로 일반화한다. 실제 노출 arm이나 신원, 보상 값을 임의로 바꾸거나 관측창을 조용히 잘라도 된다는 뜻은 아니다. 소량 유실 허용도 체계적 편향을 허용한다는 뜻이 아니다.

## 권장 구조와 구현 순서

1. **먼저 기존 배정 재사용을 로컬화한다.** 호스트가 전달하는 서명된 배정 상태와 메모리 정책으로 판단한다. 신규 배정·재배정·로그인 충돌은 당분간 기존 중앙 subject 조정 경로를 유지한다. 매 요청 중앙 조회를 없애는 것과 모든 중앙 조정을 없애는 것은 별개의 작업이다.
2. **중앙 정책 계산을 주기화한다.** shard 통계 게시와 정책 발행을 한 주기로 묶어 시작한다. 불변 정책 스냅샷을 KV 하나로 배포하고 Worker 메모리에서 재사용한다. 처음부터 Cache API, 별도 정책 DO, 다중 캐시 계층을 추가하지 않는다. 초기 단계에서는 Experiment.reserve의 현행 선택 알고리즘을 유지하고 KV 스냅샷은 우선 기존 배정의 운영 상태 확인에 사용한다. 점수 계산과 신규 arm 선택 확률까지 호스트 요청 밖으로 옮기는 것은 4번의 후속 단계다.
3. **이벤트 전송·저장을 합친다.** 같은 요청의 실제 이벤트를 Queue 메시지에 묶고, 반복 held decision 로그와 shard 쓰기를 줄인다. 실제 노출 및 goal 기록은 유지한다. 기존 중앙 관측·귀속·지연 정정 원장을 재사용한다.
4. **완전한 로컬 신규 선택은 후속 단계로 둔다.** 동시 최초 요청과 기기 간 충돌을 해결하지 않은 채 기본값으로 켜지 않는다. 우선 중앙 subject가 스냅샷 확률로 선택하게 하면 실험별 실시간 예약 RPC를 줄이면서 subject 단위 직렬화는 유지할 수 있다. 이것도 현행 bootstrap 알고리즘 변경이므로 아래 시뮬레이션이 선행되어야 한다.

## 요청 경로와 stale-while-revalidate

기본값은 **원격 준비를 기다리지 않고, 사용 가능한 상태로 즉시 결정**하는 방식이다. 정책에는 fresh 기간과 사용 가능한 최대 나이를 별도로 둔다. HTTP 캐시 헤더에 동작을 맡기는 것이 아니라 라이브러리의 정책 스냅샷 캐시에 SWR 패턴을 적용한다.

| 상황 | 동작 | 요청의 원격 대기 |
| --- | --- | --- |
| fresh 정책 + 안전하게 재사용 가능한 배정 | 로컬 검증 후 같은 arm 반환 | 없음 |
| stale이지만 최대 나이 이내인 정책 + 안전한 배정 | 기존 정책으로 즉시 반환하고 백그라운드 갱신 | 없음 |
| 정책 없음 또는 최대 나이 초과 | 서비스 기본 동작으로 해당 요청·실험 미참여, 백그라운드 확보 | 없음 |
| 최초 배정·재배정·uid 통합 결과가 준비되지 않음 | 해당 요청·실험 미참여, 명시적 준비 경로 사용 | 기본 결정 API에서는 없음 |

미참여는 사용자 영구 제외가 아니다. 이후 요청에서 정책과 배정 상태가 준비되면 참여할 수 있다. 기존 배정의 관측·신원 규칙을 충족하는 경우에만 재사용하며, SWR을 근거로 만료된 배정 증명이나 다른 uid 상태를 사용하지 않는다.

정책 갱신은 요청이 촉발하고 ctx.waitUntil로 응답과 분리한다. 동일 isolate·사이트의 중복 갱신 시작을 억제하고 실패 시 짧은 backoff를 둔다. 요청 간 진행 중 I/O Promise 공유에 의존하지 않고, 갱신 중 표시에는 만료 시각을 두어 실패 후 영구 잠금을 피한다. 이는 전역 잠금이나 isolate 생존 보장이 아니다. 검증된 더 최신 revision만 스냅샷 전체로 교체하고, 실패하면 기존 정책을 최대 나이까지만 유지한다. 동일/이전 revision 재수신은 fresh 기간이나 최대 나이를 연장하지 않는다. 다음 읽기 시도 시각은 별도로 제한해 오래된 KV 값 때문에 매 요청마다 읽는 상황을 피한다.

호스트의 기존 인증/업무 처리와 준비 작업을 겹치는 것은 가능하다. 결정 시점까지 준비되지 않았다면 기본 결정 API는 기다리지 않는다. 별도의 prepare API를 호스트가 await하면 그 대기는 전체 응답 지연에 포함한다. 응답 후 uid 준비 결과를 다음 요청에 전달하는 실제 세션 경로는 여전히 필요하며 isolate 메모리만으로 해결하지 않는다.

사용자는 드문 콜드 미참여를 허용했다. 다만 isolate 교체 빈도에 따라 드물지 않을 수 있으므로 첫 요청·고유 사용자·실험별 적격 결정 각각을 분모로 미참여율을 측정한다. 지역·신규/재방문·로그인별 차이와 연속 미참여도 확인한다. 측정만으로 편향이 사라지지는 않는다. 전체 평균이 낮아도 특정 사용자군에서 반복되면 허용 범위로 보지 않는다. 후속 답변으로 실험별 참여 대상 요청 중 정책·안전한 배정 미준비로 건너뛴 비율을 1% 이하로 유지하는 운영 목표를 확정했다. 이는 실측 보장이나 특정 사용자군의 편중을 허용하는 기준이 아니다. 빈도가 높으면 준비 전달·캐시 재사용을 개선하고, 짧은 대기를 허용하는 옵션은 별도 선택으로 남긴다. 자동으로 요청 대기를 늘리지 않는다. 영구 오프라인 기본 정책은 추가하지 않는다.

## 정책 최신성과 배정 유효성

후속 답변으로 fresh 기간 60초와 정책 최대 나이 5분을 조정 가능한 초기값으로 확정했다. 발행 주기는 60초를 시작 후보로 둔다. 발행 후 60초부터 5분까지는 stale 상태로 사용하면서 갱신한다. 이 값들은 설정 가능한 시작값이며 측정 결과가 아니다. 중지한 arm도 기존의 유효한 정책에 따라 최대 5분가량 더 노출될 수 있다는 절충을 허용한다. 요청이나 호스트 예약 실행이 없을 때 isolate의 정기 갱신을 보장하지 않는다. 발행 시각을 기준으로 만료하며 다시 읽었다고 수명을 연장하지 않는다.

운영 상태와 역사적 계산 설정의 역할을 구분한다.

- 현재 유효한 정책에서 arm/실험 중지를 확인하면 기존 배정이라도 사용하지 않는다. 삭제는 새 정책의 비활성 상태로 처리하되 과거 귀속에 필요한 설정·기록까지 삭제하지 않는다.
- 점수만 바뀌었다면 최소 유지와 진행 중 관측을 우선한다. 과거 보상은 당시 설정으로 계산한다.
- 정책 최대 나이를 넘으면 갱신 성공을 기다리지 않고 미참여한다. 별도 장기 lease로 오래된 배정을 계속 노출시키는 기능은 처음에는 만들지 않는다.
- 따라서 장애 중 동일 arm의 연속 노출까지 보장하지 않는다. 미참여를 다른 arm으로 재배정하거나 정상 관측 완료로 기록하지 않는다. 기존 관측 상태와 실제 기록은 보존하고, 중지·충돌 등 중단 사유는 명시적으로 처리한다. 미참여가 발생한 관측을 완료 표본으로 쓸지에 대한 처리 및 민감도 검증은 출시 관문이다. 무조건 삭제해도 선택 편향이 생길 수 있다.

5분은 정상적으로 시각을 검증하는 요청에서 사용할 정책의 나이 제한이다. 모든 기기의 중지 전파 완료를 5분 이내로 보장한다는 뜻은 아니다. 긴급 즉시 중지는 이번 범위 밖이다.

## 배정 상태와 관측창

서명 상태에는 site, subject 종류와 식별자, experiment, arm, assignment ID, 정책/설정 식별자, 실제 선택 확률, assignedAt, minHoldUntil을 포함한다. 관측이 있다면 observation ID, 고정 endAt, reassignAfter도 필요하다. 개인정보를 쿠키에 평문으로 불필요하게 담지 않고 크기 상한을 둔다. 실험 수 무제한 요구를 단일 쿠키가 무제한 커진다는 뜻으로 구현하지 않는다. 상한 초과 상태는 호스트 세션/중앙 준비 경로에서 처리한다.

`reassignAfter = max(minHoldUntil, 현재 관측 endAt)`이며, 관측은 배정 시각이 아니라 실제 첫 노출 시각에서 시작한다. 같은 관측의 반복 노출로 종료 시각을 계속 뒤로 밀지 않는다.

토큰에 필드만 추가해 동시성 문제가 해결되지는 않는다. 초기 구현의 로컬 경로는 **권위 있는 준비 결과로 안전하게 재사용할 수 있는 구간**에 한정한다. 새 관측 개시·관측 종료 후 갱신·재배정은 명시적인 준비 경계를 통과시킨다. 호스트는 실제 노출 API의 갱신 상태를 응답 전 세션/쿠키에 반영해야 한다. 응답 후 노출이나 오래된 동시 요청의 상태를 다음 요청에 반영할 수 없는 통합에는 이 빠른 경로를 보장하지 않는다.

준비 처리에서 이전 노출이 아직 Queue에 있다는 이유로 관측이 없다고 판단하여 재배정해서는 안 된다. 노출 접수 확인/세션 revision 등으로 이전 구간을 안전하게 마감하는 구체 프로토콜과 동시 요청 검증이 필요하다. 이는 아직 구현 전 관문이다. 이를 해결하지 못하면 로컬화 최적화를 보류하고 기존 중앙 경로를 유지한다. 기존 경로 자체가 Queue 지연과 재배정 경합을 자동 해결한다는 뜻은 아니며, 그 경로도 해당 정확성 검증을 통과해야 한다. 임의의 추가 대기 시간만으로 정확성을 증명하지 않는다.

## uid 통합의 완료 경로

인증 또는 세션 갱신 시 호스트가 `prepare`에 해당하는 명시적인 API를 호출하고, 반환된 서명 상태를 호스트 세션 또는 실제 응답에 저장한다. 이름은 가칭이다. 응답 후 메모리에서 조회가 끝났다는 사실만으로 다음 요청이 준비되었다고 간주하지 않는다.

중앙 uid 원장은 실험별로 기존 uid 배정을 우선하고, 없으면 유효한 cid 상태를 채택하며, 둘 다 없으면 새 배정을 만든다. 이 조정은 원자적으로 수행한다. uid에 다른 실험이 있다는 이유로 cid의 모든 실험을 버리지 않는다. 최초 배정과 재배정 조정을 중앙에 남겨 기기별 임시 선택 모드는 처음부터 제공하지 않는다.

다른 기기의 오래된 서명 상태까지 즉시 무효화하는 것은 원격 확인 없이 보장할 수 없다. 세션 갱신/전환 프로토콜에서 기기 간 충돌 및 오래된 상태의 유효 구간을 검증해야 한다. 엄격한 신원 일관성이 필요한데 이 통합을 제공하지 못하는 경우 중앙 확인 경로를 유지한다. **모든 요청 무대기·모든 첫 요청 참여·항상 기기 간 동일 배정**을 동시에 약속하지 않는다.

## 노출 등록, 이벤트 손실과 배치

후속 로컬 신규 선택을 도입한다면 배정 증명과 노출을 같은 처리 단위에 넣는다. 증명에는 당시 arm·확률·관측 설정과 버전이 있어야 한다. 과거 배정 등록은 역사 기록이며 현재 canonical 배정을 Queue 도착 순서대로 바꾸는 명령이 아니다. 늦게 온 노출과 충돌한 실제 노출도 보존하고 기존 정정 경로로 재구성한다. 현재 원장과 일치하지 않는 노출을 거절하는 코드를 그대로 재사용할 수 없다.

미참여 선택과 수집 이벤트 손실은 구분한다. 노출만 사라지면 공통 goal의 균등 귀속 분모가 달라지고, goal만 사라지면 거짓 0 보상이 생길 수 있다. 가능한 동일 요청의 배정 증명·노출·goal을 함께 전송한다. 이것이 다른 요청에서 발생한 goal까지 원자적으로 묶는다는 뜻은 아니다. 의도적 감량이 필요하다면 결과와 무관한 subject/cohort 단위 샘플링을 별도로 설계하며, 처음에는 추가하지 않는다. waitUntil만으로 무편향 전달을 보장하지 않는다.

Queue 포장은 버전 있는 envelope, 바이트 기준 분할, 이벤트별 ID·검증·멱등성으로 구현한다. 영구적으로 잘못된 항목은 식별 가능한 오류로 분리하고 정상 항목을 처리한다. 일시 오류는 메시지 전체를 재시도하되 이미 성공한 이벤트는 중복 적용하지 않는다. 별도 범용 부분 재시도 시스템은 만들지 않는다.

## 신규 arm과 지연 학습

실시간 pending 예약 제거는 단순 캐시 최적화가 아니라 알고리즘 변경이다. 기존 예약 건수 제한 대신 지연된 통계에 기반한 확률 제한으로 바뀐다. 신규 arm 전체에 배정할 총 탐색 예산과 각 arm 상한을 정하고 기존 arm에 남는 확률을 재정규화한다. 모든 arm이 신규여서 상한을 동시에 만족할 수 없는 경우에는 별도의 균등 초기화 규칙이 필요하며 그 예외를 명시한다. 실제 적용한 최종 확률을 기록한다.

확률 상한은 배정 건수 상한이 아니다. 대략 신규 배정 유입률 × 피드백 지연 × 배정 확률만큼 완료 전 배정이 누적될 수 있다. 60초 갱신뿐 아니라 7일 관측창, 다수 신규 arm, Queue 지연, 트래픽 급증, 양·음수 보상, 1년 이상 추세 변화로 검증한다. 정책별 확률 변화폭 제한은 처음부터 추가하지 않고 이 검증에서 필요할 때만 도입한다.

## 리뷰 반영과 검증 관문

두 리뷰어의 중복 의견을 통합하여 모두 수용했다: 콜드 모집단 편향, 관측 종료 보호, 중지 우선순위, uid 준비 결과 전달, 도착 순서와 역사 기록 분리, 지연 bootstrap, 배치 재시도. 다만 이를 한 번에 구현하면 복잡해지므로 완전 로컬 신규 선택을 후속 단계로 이동했다. 단일 정책 배포 경로와 기존 중앙 원장 재사용을 우선한다.

구현 합격 기준:

- 유효 정책과 안전하게 재사용 가능한 배정 상태가 있는 warm 요청의 외부 I/O 0회와 추가 CPU·p50/p95/p99 측정. 서명/쿠키 비용을 포함한다.
- fresh/stale/cold/최대 나이 초과 및 로그인별 지연과 참여율; 지역/방문 빈도별 차이, 연속 미참여와 유실 패턴 확인. 갱신 실패·동시 요청·동일/이전 revision 수신·isolate 교체 시에도 원격 대기를 추가하지 않는지 검증.
- 최소 유지 1일/관측 7일, 반복 관측, 응답 후 노출, 동시 최초 요청, 오래된 쿠키 덮어쓰기, 지연 Queue 뒤 재배정 검증.
- uid 기존 배정 우선, 실험별 cid 채택, 다른 기기 갱신·중지와 충돌 검증.
- 늦은 노출/goal의 실제 arm 및 균등 귀속 보존, 중단 관측과 정상 0의 구별.
- 배치 부분 성공 후 재시도, 잘못된 항목, 메시지 크기 분할 검증.
- 중앙 예약 없는 정책의 장기 시뮬레이션 후 알고리즘 교체 판단.
- 비용은 수집 이벤트뿐 아니라 배정 조회·캐시 miss·활성 실험 수·메시지 크기·중앙 준비 빈도로 계산한다. 대기 시간 제한이 호출 비용 제한은 아니다.

현재 원격 정책/배정 경로는 resolveHome → Subject.decide → Experiment.getConfig/reserve이다. 기존 코드의 최소 유지/관측 규칙은 src/core/observation.ts에 있다. 기존 uid에 없는 개별 실험의 cid 인계는 미완료다.

이전 구현 검증: npm run check는 9개 파일/70개 테스트, 타입 검사와 빌드 통과. workerd RPC result disposal 경고 1회가 있었다. 패키지 검증도 통과했으나 이 결과는 본 계획의 검증이 아니다. 이번 작업은 문서 리뷰이며 새 코드 테스트·배포·성능 측정을 수행하지 않았다.
