# 구현 및 검증 범위

[문서 안내](README.md) · [설계](../DESIGN.md) · [구현 구조](../TECHNICAL_DESIGN.md)

현재 구현은 로컬 배정, 서버 요청 래퍼, CSR 클라이언트/서버 어댑터, Queue 원본 수집, Basin 조회 기반 고정 마감 학습, 두 Durable Object의 정책 관리, R2 재시도 결과 고정, 원본 분석 API까지 연결한다. 이전 사용자별 Subject/Identity/Shard 객체와 예약·보상 정정 경로는 제거했다.

로컬 검증은 TypeScript, 순수 코어 테스트, workerd의 DO/R2/Queue 테스트, 생성 SQL의 SQLite 호환 실행, 패키지 외부 소비자 및 DOM 전용 브라우저 타입 검사, 신규 설치 Worker 번들 dry-run을 사용한다. 실제 노출→원본→학습→정책, 재시도/eviction 중 중복 학습 방지, 로그인 귀속, 음수/큰 보상, 늦은 사건과 확정 보상 차이, CSR 인증 전환과 준비/노출 경합을 검사한다.

Basin SQL의 실행 계획과 5,165사건/300표본 fixture를 이용한 원격 학습 전후 비교는 [측정 기록](ISSUE-1-PERFORMANCE.md)에 있다. 새 구조의 요청 경로 부하 테스트와 전체 비용 검증은 아직 남아 있다. SQLite 호환 실행은 Cloudflare 프로덕션 쿼리 실행을 대신하지 않는다. 과거 부하/비용 문서는 v1의 기록이며 이 구현의 성능이나 절감률로 인용하지 않는다. 하루 100만 사건은 설계 가정이지 검증된 처리량이 아니다.

도입 전에는 신규 테스트 Worker에 설치하여 Stream fan-out, Basin 쿼리, alarm 마감, 이후 정책 반영을 실제로 확인하고, 기존 기본 화면 대비 지연·미참여율·arm별 수집 유실을 측정한다. 한 표본이 조회 한도를 넘는 경우 학습 커서가 지연될 수 있으므로 대량 활동 uid도 확인한다. 구체적인 한도와 배포 전환은 구현 구조 문서를 따른다.

이 버전의 템플릿은 신규 설치용이다. 기존 v1 배포/데이터의 자동 마이그레이션 및 삭제는 구현하지 않으며, 코드 수정만으로 원격 리소스를 변경하지 않는다.
