# 현재 엔진의 로그 스트림 검증

2026-10-25 기준. 고정 시드의 가상 웹 방문을 실제 로컬 선택 함수 → SQLite 증분 학습 → 관측 마감/outbox → 정책 계산으로 연결한다. 6개 검사를 일반 테스트에 포함하며, 별도 서버나 유료 리소스 없이 실행한다. 실행 코드는 [테스트](https://github.com/corca-ai/eye/blob/main/test/core/engine-stream.test.ts), [스트림 생성기](https://github.com/corca-ai/eye/blob/main/test/helpers/engine-stream.ts), 수치는 [결과 JSON](engine-stream-results.json)에 있다. 아래 명령은 테스트 소스를 포함한 저장소 체크아웃에서 실행한다.

```sh
npm ci
npm run test:engine

# 선택 사항: 결과 갱신 및 첫 고정 A/A 실행의 수신 로그 저장
EYE_STREAM_REPORT=docs/engine-stream-results.json \
EYE_STREAM_LOG=/tmp/eye-web-stream.ndjson npm run test:engine

# 전체 회귀·타입·문서·패키지 검증
npm run check
npm run check:package
```

JSON은 6개 검사가 모두 통과했을 때 기록한다. 실패한 실행에서는 기존 파일이 남으므로, 성공 종료 여부를 함께 확인한다. NDJSON은 `{siteId, receivedAt, event}` 형태이며 수신 순서와 중복을 보존한다. 실사용자 정보는 사용하지 않는다.

## 입력과 검증 범위

- 방문의 75%는 모사한 하루의 09~21시에 집중하고 나머지는 전 시간대에 분포한다. 모바일 65%, 데스크톱 35%로 구매율에 차이를 둔다.
- 방문마다 동일 표본의 노출 3회와 일반 행동 로그 4개를 보낸다. 익명·로그인 상태, 방문 도중 로그인, 동일 uid의 다른 기기 구매, 로그아웃을 섞는다.
- 구매는 노출 2분 뒤에 발생한다. 구매 금액은 20 또는 100이며 구매의 약 10%는 4분 시점에 절반을 음수 환불한다. 미구매 방문도 보상 0인 표본으로 마감한다.
- 기본 전달 지연은 0~1초, 약 2%는 10~90초다. 5초 수신 묶음과 최대 100건 청크를 사용하고 약 3%를 중복 전달한다. 희소한 순서 역전은 현재 엔진의 계약대로 처리한다.
- 관측 10분, 도착 유예 2분, 귀속 창/반감기 1시간, 학습 반감기 12시간, 정책 갱신 15분을 사용한다. 테스트 시간을 압축한 설정이며 운영 기본값의 장기 성능을 주장하지 않는다.

매 실행에서 모든 방문이 정확히 한 번 마감되는지, 보상·정책 점수가 유한한지, 배정 확률 합과 최소 탐색률, outbox 소진, 시간 범위에 해당하는 요약의 표본 수·보상 합도 검사한다. 미래 구매 결과는 배정 시점에 공개하지 않는다. 행동과 전달 오류의 난수열은 분리한다.

총 24,640방문·204,496개 이벤트를 생성한다(재전송 건수 제외, 시나리오별 합계). 로컬에서 전용 검사는 약 8초 걸렸으며 시간 자체를 성능 합격 기준으로 삼지 않는다. 이번 스트림 검증에서 재현된 엔진 결함은 없어 제품 코드는 변경하지 않았다.

고정 A/A의 통계량은 독립 방문·고정 종료 시점을 가진 이 입력에서 큰 편향을 탐지하는 검사다. 실제 서비스의 반복 사용자·다중 검정·중간 중단까지 보정한 실험 분석 기능은 아니다. 적응형 A/A는 우연한 초기 성과 차이를 따라 한 실행에서 크게 기울 수 있다. 이를 거짓 승리 선언으로 해석하거나 배정이 반드시 50:50이어야 한다고 검사하지 않는다. 8개 시드는 대략적인 편향 회귀 검사이며 거짓 양성률을 정밀하게 보증하지 않는다.

원본 리듀서 비교는 입력 순서가 유지된 경우에만 정확한 일치를 요구한다. 작은 지연을 포함한 실행에서는 늦은 과거 노출이 무시되는 진단이 발생하며, 이미 처리한 골의 귀속을 다시 계산하지 않는 현재 계약을 유지한다. 이 검증을 위해 재정렬 버퍼나 추가 원본 스캔을 도입하지 않았다.

## 경계

선택·이벤트 검증·증분 상태·마감·요약·정책 수학은 실제 코드와 메모리 SQLite를 사용한다. 정책 갱신/모멘트 반영은 하네스가 연결하며, 실제 SDK HTTP 경로·두 Durable Object 간 RPC·Queue·Stream 전송·디스크 쓰기·네트워크 지연은 재현하지 않는다. `track`도 로그 스트림에 포함하지만 실제 수집 경로의 학습 우회 비용은 측정하지 않는다. 기존 workerd 테스트가 별도로 outbox 재시도, eviction, 중복 학습 방지 등을 검사한다.

방문은 서로 독립된 사용자이며 장기간 재방문, 다중 실험, 작은 효과의 검출력, 도착 유예를 넘는 지연, 고장 주입 전체 조합은 이번 모사 범위에 포함하지 않는다. 실제 Cloudflare 처리량·운영 비용·수집 유실률은 배포 환경의 별도 측정이 필요하다.
