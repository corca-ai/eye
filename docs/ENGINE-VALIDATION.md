# 현재 엔진의 로그 스트림 검증

2026-10-30 기준. 고정 시드의 가상 웹 방문을 실제 로컬 선택 함수 → SQLite 증분 학습 → 관측 마감/outbox → 정책 계산으로 연결한다. 6개 검사를 일반 테스트에 포함하며, 별도 서버나 유료 리소스 없이 실행한다. 실행 코드는 [테스트](https://github.com/corca-ai/eye/blob/main/test/core/engine-stream.test.ts), [스트림 생성기](https://github.com/corca-ai/eye/blob/main/test/helpers/engine-stream.ts), 수치는 [결과 JSON](engine-stream-results.json)에 있다. 아래 명령은 테스트 소스를 포함한 저장소 체크아웃에서 실행한다.

```sh
npm ci
npm run test:engine

# 선택 사항: 결과 갱신 및 첫 고정 A/A 실행의 수신 로그 저장
EYE_STREAM_REPORT=docs/engine-stream-results.json \
EYE_STREAM_LOG=/tmp/eye-web-stream.ndjson npm run test:engine

# 전체 회귀·타입·문서·패키지 검증
npm run check
npm run check:package
```

JSON은 6개 검사가 모두 통과했을 때 기록한다. 실패한 실행에서는 기존 파일이 남으므로, 성공 종료 여부를 함께 확인한다. NDJSON은 `{siteId, receivedAt, event}` 형태이며 수신 순서와 중복을 보존한다. 실사용자 정보는 사용하지 않는다.

## 입력과 검증 범위

- 방문의 75%는 모사한 하루의 09~21시에 집중하고 나머지는 전 시간대에 분포한다. 모바일 65%, 데스크톱 35%로 구매율에 차이를 둔다.
- 방문마다 동일 표본의 노출 3회와 일반 행동 로그 4개를 보낸다. 익명·로그인 상태, 방문 도중 로그인, 동일 uid의 다른 기기 구매, 로그아웃을 섞는다.
- 구매는 노출 2분 뒤에 발생한다. 구매 금액은 20 또는 100이며 구매의 약 10%는 4분 시점에 절반을 음수 환불한다. 미구매 방문도 보상 0인 표본으로 마감한다.
- 기본 전달 지연은 0~1초, 약 2%는 10~90초다. 5초 수신 묶음과 최대 100건 청크를 사용하고 약 3%를 중복 전달한다. 희소한 순서 역전은 현재 엔진의 계약대로 처리한다.
- 관측 10분, 도착 유예 2분, 귀속 창/반감기 1시간, 학습 반감기 12시간, 정책 갱신 15분을 사용한다. 테스트 시간을 압축한 설정이며 운영 기본값의 장기 성능을 주장하지 않는다.

매 실행에서 모든 방문이 정확히 한 번 마감되는지, 보상·정책 점수가 유한한지, 배정 확률 합과 최소 탐색률, outbox 소진, 시간 범위에 해당하는 요약의 표본 수·보상 합도 검사한다. 미래 구매 결과는 배정 시점에 공개하지 않는다. 행동과 전달 오류의 난수열은 분리한다.

총 24,640방문·204,496개 이벤트를 생성한다(재전송 건수 제외, 시나리오별 합계). 로컬에서 전용 검사는 약 8초 걸렸으며 시간 자체를 성능 합격 기준으로 삼지 않는다. 이번 결과는 cold 배정 개선 후 다시 실행한 수치다. 기존 전달·귀속 검증에 더해 아래 정책 비교를 수행했다.

고정 A/A의 통계량은 독립 방문·고정 종료 시점을 가진 이 입력에서 큰 편향을 탐지하는 검사다. 실제 서비스의 반복 사용자·다중 검정·중간 중단까지 보정한 실험 분석 기능은 아니다. 적응형 A/A는 우연한 초기 성과 차이를 따라 한 실행에서 크게 기울 수 있다. 이를 거짓 승리 선언으로 해석하거나 배정이 반드시 50:50이어야 한다고 검사하지 않는다. 8개 시드는 대략적인 편향 회귀 검사이며 거짓 양성률을 정밀하게 보증하지 않는다.

원본 리듀서 비교는 입력 순서가 유지된 경우에만 정확한 일치를 요구한다. 작은 지연을 포함한 실행에서는 늦은 과거 노출이 무시되는 진단이 발생하며, 이미 처리한 골의 귀속을 다시 계산하지 않는 현재 계약을 유지한다. 이 검증을 위해 재정렬 버퍼나 추가 원본 스캔을 도입하지 않았다.

## 경계

선택·이벤트 검증·증분 상태·마감·요약·정책 수학은 실제 코드와 메모리 SQLite를 사용한다. 정책 갱신/모멘트 반영은 하네스가 연결하며, 실제 SDK HTTP 경로·두 Durable Object 간 RPC·Queue·Stream 전송·디스크 쓰기·네트워크 지연은 재현하지 않는다. `track`도 로그 스트림에 포함하지만 실제 수집 경로의 학습 우회 비용은 측정하지 않는다. 기존 workerd 테스트가 별도로 outbox 재시도, eviction, 중복 학습 방지 등을 검사한다.

방문은 서로 독립된 사용자이며 장기간 재방문, 다중 실험, 작은 효과의 검출력, 도착 유예를 넘는 지연, 고장 주입 전체 조합은 이번 모사 범위에 포함하지 않는다. 실제 Cloudflare 처리량·운영 비용·수집 유실률은 배포 환경의 별도 측정이 필요하다.

## 저트래픽·초기 탐색 정책 비교

[정책 시뮬레이션](https://github.com/corca-ai/eye/blob/main/test/core/policy-simulation.test.ts)은
각 시나리오에서 고정 시드 1~32를 기존 배정 규칙과 개선 규칙으로 각각 실행한다.
점수 계산은 동일하며 기존의 all-cold 균등 배정과 cold 고정 예산만 비교 기준으로 고정했다.
작은 인접 시드의 첫 선택 쏠림을 피하려고 난수열을 8회 진행한 뒤 사용한다. 선택 난수와 보상 난수를 분리하고 두 arm의 잠재 보상을 공통 난수로 생성한다.
선택된 보상만 관측 종료 후 학습한다. 매 선택의 확률 합과 탐색 하한도 확인한다.
이것은 정책 수학 시뮬레이션이며 실제 HTTP·Queue·DO 통합의 대체 검증이 아니다.

기본 학습 반감기 14일, 관측 지연 7일을 사용한다. 저트래픽은 1,600일간 4일마다 한 번 선택하고,
나머지는 400일간 하루 4번 선택한다. 지연 시나리오는 완료 지연이 21일이다.
나쁜 신규 arm은 기존 arm의 1,000개/+100과 신규 arm의 7개/−100에서 시작한다.
고액 희소 보상은 한 arm의 평균 0.5와 다른 arm의 5% 확률 보상 20(기댓값 1)을 비교한다.
우세 전환은 기간 절반에서 평균 1과 0을 교환한다. 나머지 보상에는 ±0.1 균등 잡음을 더한다.

아래 값은 선택한 arm의 알려진 기댓값 합을 매 선택의 최선 기댓값 합으로 나눈 시드 평균이다.
실현 보상과 후반 우수 arm 배정률도 [결과 JSON](policy-simulation-results.json)에 기록했다.

| 시나리오 | 기존 | 개선 |
| --- | ---: | ---: |
| 저트래픽 | 49.88% | 74.26% |
| 나쁜 신규 arm | 79.33% | 86.29% |
| 희소 고액 보상 | 92.94% | 92.96% |
| 21일 지연 보상 | 87.86% | 91.08% |
| 우세 전환 | 85.58% | 87.64% |

```sh
EYE_POLICY_REPORT=report/policy-simulation.json npm run test:core -- test/core/policy-simulation.test.ts
```

합격 조건은 두 문제 시나리오에서 기준 대비 5%p 초과 개선, 나머지에서 최선 기댓값 대비
10%p 이내의 기준 대비 손실, 고액 희소 보상을 제외한 후반 우수 arm 배정률 65% 초과다.
고액 희소 보상에서는 차이가 약 0.02%p로 작다. 모든 분포에서 우월하다는
주장은 하지 않는다. 32개 시드는 통계적 보장이나 운영 수익의 예측치가 아니다.
기준 직전·동일·직후 가중치, 동점, 다수 신규 arm, 100% 탐색, 단위 변환은 별도 단위 테스트로 검증한다.
