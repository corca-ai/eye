# 조회·Queue 정규화

기준 `8f3b611`. 공개 API, 보상 수학과 수집 예산을 유지하며 동등한 요청과 반복 설정을 정리한다. [원시 로컬 측정](measurements/normalize-pack-results.json)은 정확한 복원/조회 결과 일치를 검사한 뒤 한 번 예열·다섯 번 측정한 중앙값이다.

## 필터와 캐시

AND/OR의 결합·교환·멱등법칙만 사용한다. 같은 연산을 평탄화하고 자식을 정렬·중복 제거하며 한 자식인 그룹을 접는다. NOT 안에서도 같은 정리만 하고 분배법칙·부정 전개·숫자 재정렬은 하지 않는다. 원본 요청의 SQL 검증, 필터 노드·깊이와 JSON 깊이·32KB 검사를 통과한 뒤 별도의 캐시 표현을 만든다. 원래 저장 요청은 실행과 page().request에 유지한다.

정규화 대상은 지원 조회의 filter와 hasEvent.filter다. groupBy와 in의 값 등 나머지 배열 순서, 종류·시간·limit·cursor·권한 scope·신선도 계약을 유지한다. 인공 예시 세 요청의 캐시 표현이 3개에서 1개가 된 것은 실제 트래픽의 적중률이나 원격 쿼리 절감률 측정이 아니다.

## 완료 관측의 우선순위

완료 관측은 pending revision 1을 덮어쓰므로, 같은 조건에서 보이는 높은 revision의 완료 ID는 노출 정렬 전에 제외한다. 완료의 중복 전송은 여전히 마지막 revision 순위로 제거한다. 스냅샷 수신 상한과 실험/arm/generation 조건을 완료 키에도 적용하고, 귀속용 노출과 학습은 바꾸지 않는다.

| 관측 1,000개·노출 5,000개 | 정렬 입력 이전→현재 | 로컬 이전→현재 ms |
| --- | ---: | ---: |
| 완료 없음 | 5,000→5,000 | 74.97→71.55 |
| 완료 950개, 일부 완료 재전송 포함 | 5,000→250 | 71.84→25.54 |

원본 읽기와 완료 ID 조인은 남는다. 작은 차이는 잡음에 민감하며 완료가 없는 조회까지 항상 빨라진다는 보장은 없다. SQLite 실행은 실제 Basin 계획·스캔 바이트·과금 검증을 대신하지 않는다.

## 메시지 안의 설정 사전

원본 envelope당 크기와 ingest 전체 크기를 먼저 검사한다. 일반 포장이 두 메시지 이상이 될 때만 노출 설정의 사전화 후보를 만든다. 후보는 메시지마다 독립적인 사전과 숫자 참조를 담으며, 실제 JSON 프레이밍과 사전 바이트를 포함해 나눈다. 일반 표현보다 메시지 수가 적을 때만 선택한다. 작은 배치에서 바이트만 줄이려고 복원 CPU를 추가하지 않는다.

복원 시 사전은 최대 100개이며 각 설정을 검사한다. 참조는 유한한 비음수 안전 정수여야 하고 사전 범위 안에 있어야 한다. envelope를 만들기 전에 확장 크기를 계산하고, 설정 객체는 사건별로 복사한다. 잘못된 항목/참조는 해당 사건만 거절하고 정상 형제는 처리한다. 잘못된 메시지 래퍼·사전 배열 구조는 메시지 단위 오류다. 원본 Stream 레코드는 복원 뒤 기존 파서에서 생성하며, Queue 재전송의 학습 중복 방지도 그대로다.

| 입력 | 메시지 이전→현재 | JSON 바이트 이전→현재 | 포장 이전→현재 ms | 복원 이전→현재 ms |
| --- | ---: | ---: | ---: | ---: |
| track 100개 | 1→1 | 15,304→15,304 | 0.046→0.046 | 0.0007→0.0008 |
| 같은 설정 노출 20개 | 1→1 | 13,364→13,364 | 0.024→0.023 | 0.0002→0.0002 |
| 같은 설정 노출 100개 | 2→1 | 66,908→41,159 | 0.117→0.212 | 0.0007→0.099 |
| 서로 다른 설정 노출 100개 | 2→2 | 66,998→66,998 | 0.115→0.212 | 0.0007→0.0008 |

큰 배치의 후보 생성과 사전 복원에는 CPU가 더 든다. 설정이 모두 달라도 비교 비용은 발생한다. 메모리·CPU·요청 지연·재시도를 포함한 운영 검증은 별도다. [Queue 과금 문서](https://developers.cloudflare.com/queues/platform/pricing/)의 작업 단위는 메시지별 64,000바이트이며 내부 메타데이터가 약 100바이트 추가된다. 원시 결과의 단위 수는 이를 적용한 추정치이며 실제 청구액이 아니다. 메시지가 줄어도 재시도 시 정상 형제의 재전송 범위는 커질 수 있다.

## 재현

```sh
npm ci
npm run build

node /tmp/eye-normalize-benchmark.mjs /tmp/eye-normalize-base/dist
npm run check
npm run check:package
```
